I will enable CSRF (Cross-Site Request Forgery) protection.

Up until now, we disabled CSRF (```http.csrf().disable()```) for simplicity. However, in a real production environment, this is dangerous. Enabling it ensures that every POST request (Login, Register, Logout) comes from your actual application and not a malicious third-party site.

**1. Update Security Configuration (```SecurityConfig.java```)**

We simply remove the line ```.disable()``` or explicitly default it. Spring Security 6+ (Spring Boot 3) enables it by default, but it's good practice to be explicit.

```Java```
```
package com.ignou.lab.config;

// ... imports ...

@Configuration
public class SecurityConfig {

    // ... (Encoder and Provider beans remain the same) ...

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/showMyLoginPage", "/register", "/processRegistration", "/resources/**", "/webjars/**").permitAll()
                .anyRequest().authenticated()
            )
            .formLogin(form -> form
                .loginPage("/showMyLoginPage")
                .loginProcessingUrl("/authenticateTheUser")
                .defaultSuccessUrl("/api/students", true)
                .permitAll()
            )
            .logout(logout -> logout
                .logoutUrl("/logout")
                .logoutSuccessUrl("/showMyLoginPage?logout")
                .permitAll()
            );
            
        // REMOVE this line: http.csrf().disable();
        // OR Explicitly Enable (Optional, as it's default):
        http.csrf(csrf -> csrf.ignoringRequestMatchers("/api/**")); // (Optional) Ignore CSRF for external REST APIs if needed

        return http.build();
    }
}
```

**2. Update HTML Forms (Thymeleaf)**

When CSRF is enabled, Spring Security expects a hidden input field named _csrf in every POST form. Thymeleaf adds this automatically if you use the th:action attribute.

However, if you used standard HTML ```action``` or for specific manual forms (like Logout), you might need to check them.

**A. Update Login Page (```login-page.html```) Ensure you are using ```th:action```.**

```HTML```
```
<form th:action="@{/authenticateTheUser}" method="POST">
    </form>
```
**B. Update Registration Page (registration-page.html)**
```HTML```
```
<form th:action="@{/processRegistration}" th:object="${userDto}" method="POST">
    </form>
```
**C. Update Logout Button (Crucial Change) With CSRF enabled, Logout must be a POST request. A simple <a> link (GET request) is no longer secure by default. You must change your logout link to a small form.**

File: ```student-list.html```

```HTML```
```
<form th:action="@{/logout}" method="POST" class="d-inline">
    <button type="submit" class="btn btn-danger btn-sm">Logout</button>
</form>
```

**3. How to Verify CSRF is Working**

1. **Start the Server.**
2. **Go to Login Page**: ```http://localhost:8080/showMyLoginPage```
3. **Inspect Source**: Right-click on the page -> **View Page Source.**
4. **Find the Token**: Look inside the ```<form>``` tag. You will see a hidden input automatically generated by Spring/Thymeleaf:

```HTML```
```
<input type="hidden" name="_csrf" value="Ck1b-8xJ5-..." />
```
5. **Test Logout**: Login, then click Logout. If it works, CSRF is successfully validated. If you get a "403 Forbidden" or "Method Not Allowed" on logout, it means you didn't switch the logout link to a POST form.
