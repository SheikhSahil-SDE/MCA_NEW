# 15. Setup a CBR transmission between these nodes.

We will replace the simple Echo application with a Constant Bit Rate (CBR) transmission. In NS-3, CBR is typically implemented using the OnOffApplication, which generates a steady stream of data at a specified rate.


**​Step-by-Step Instructions**

* ​Receiver Setup (n2): Install a PacketSink application. This is a generic receiver that accepts traffic on a specific port and records the total bytes received.
* ​Sender Setup (n1): Install an OnOffApplication. This application cycles between "On" (sending data) and "Off" (idle) states. To achieve a Constant Bit Rate, you simply keep the "Off" time at zero and set a fixed "On" time and Data Rate.
* ​Configure Attributes:
​DataRate: Set the transmission speed (e.g., "500kb/s").
* ​PacketSize: Define the size of each packet (e.g., 1024 bytes).
* ​Run and Capture: Execute the script and use the generated .pcap files to verify the timing of the packets.

**​C++ Code Implementation**
​Add this logic to your 3D wireless setup.

```c++```
```
// 1. Setup the Receiver (PacketSink) on Node 1 (n2)
uint16_t port = 4000;
Address sinkLocalAddress (InetSocketAddress (Ipv4Address::GetAny (), port));
PacketSinkHelper sinkHelper ("ns3::UdpSocketFactory", sinkLocalAddress);

ApplicationContainer sinkApp = sinkHelper.Install (nodes.Get (1));
sinkApp.Start (Seconds (1.0));
sinkApp.Stop (Seconds (10.0));

// 2. Setup the CBR Sender (OnOffApplication) on Node 0 (n1)
OnOffHelper onoff ("ns3::UdpSocketFactory", 
                   Address (InetSocketAddress (interfaces.GetAddress (1), port)));

// Set for Constant Bit Rate: Fixed data rate and no "Off" time
onoff.SetAttribute ("OnTime", StringValue ("ns3::ConstantRandomVariable[Constant=1]"));
onoff.SetAttribute ("OffTime", StringValue ("ns3::ConstantRandomVariable[Constant=0]"));
onoff.SetAttribute ("DataRate", DataRateValue (DataRate ("500kbps")));
onoff.SetAttribute ("PacketSize", UintegerValue (1024));

ApplicationContainer clientApp = onoff.Install (nodes.Get (0));
clientApp.Start (Seconds (2.0));
clientApp.Stop (Seconds (10.0));

// 3. Enable Tracing
wifiPhy.EnablePcapAll ("wireless-cbr-task15");
```

**Observations for the Lab Record**

* Fixed Inter-arrival Time: When you open the .pcap file in Wireshark, you will notice that the "Time" difference between consecutive packets is identical. For 500kbps and 1024-byte packets, you should see a packet roughly every 16.3 milliseconds.
* Throughput Verification: Since the nodes are at a fixed distance in 3D space, check if the "Total Bytes Received" at n2 matches the formula: \text{DataRate} \times \text{Active Time}.
* Difference from UDP Echo: Unlike Task 14, where a client waits for a reply before sending the next packet, this CBR sender pushes data continuously regardless of whether the receiver acknowledges it, reflecting the connectionless nature of UDP described in your MCS-218 textbook.
