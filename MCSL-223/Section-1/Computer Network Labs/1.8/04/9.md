# 9. Install the optimized Link State Routing protocol on these nodes.

The Optimized Link State Routing (OLSR) protocol must be installed on the wireless mobile ad-hoc network (MANET) nodes created in Task 8.

In a wireless ad-hoc environment, nodes move dynamically, meaning paths between them are not fixed. OLSR is a proactive routing protocol specifically designed for MANETs to handle these changing topologies.

**Step-by-Step Instructions**

1. Add the Header File: You must include the OLSR module header at the top of your script: #include "ns3/olsr-module.h".
2. Initialize the OLSR Helper: Create an instance of the OlsrHelper.
3. Configure the Internet Stack: Before installing the stack on the nodes, use the SetRoutingHelper method on the InternetStackHelper. This tells the simulator to use OLSR instead of default static routing.
4. Install on Nodes: Call Install(nodes) to apply the stack and routing protocol to all nodes in the container.

**C++ Code Implementation**

This code snippet shows the necessary modifications to the MANET script.

```C++``
```
#include "ns3/olsr-module.h"

// ... (Existing node and wireless configuration from Task 8) ...

// 1. Create the OLSR Helper
OlsrHelper olsr;

// 2. Setup the Internet Stack to use OLSR
InternetStackHelper stack;
stack.SetRoutingHelper (olsr); // This assigns OLSR to all nodes

// 3. Install the stack on the nodes (n1, n2, n3)
stack.Install (nodes);

// 4. Assign IP Addresses as usual
Ipv4AddressHelper address;
address.SetBase ("10.1.1.0", "255.255.255.0");
Ipv4InterfaceContainer interfaces = address.Assign (devices);

// ... (Continue with mobility and simulation setup) ...
```
**Technical Explanation of OLSR**
As outlined in the MCS-218 textbook and the lab manual, OLSR optimizes the standard link-state algorithm for wireless environments:
* Multi-Point Relays (MPRs): Instead of every node rebroadcasting every packet (flooding), only selected nodes called MPRs are responsible for forwarding control traffic. This significantly reduces network overhead.
* Neighbor Discovery: Nodes periodically exchange HELLO messages to detect their immediate neighbors and determine link status.
* Topology Control (TC): Nodes selected as MPRs broadcast TC messages to spread link-state information throughout the entire network, allowing every node to calculate the shortest path to every other node.

**Observations for the Lab Record**

* Proactive Nature: Unlike reactive protocols (like AODV) that find routes only when needed, OLSR maintains a routing table at all times.
* Control Traffic: In the simulation traces (e.g., in Wireshark), you will see periodic HELLO packets being exchanged even if no user data is being sent.
* Routing Table Updates: As the nodes $n1, n2,$ and $n3$ move, the OLSR protocol will dynamically update the routing table to ensure the most efficient path is used.

Once the protocol is installed, the next logical step (Task 10) is typically to install an application, such as a UDP echo or a ping, to verify that the routing protocol is successfully directing traffic between nodes that may not be in direct range of one another.
