# 2. Create a simple network topology having two client node on left side and two server nodes on the right side. Both clients are connected with another node n1. Similarly, both server node connecting to node n2. Also connect node n1 and n2 thus forming a dumbbell shape topology. Use point to point link only.

We need to construct a Dumbbell Topology using NS-3. This topology is frequently used to study network congestion and bottleneck performance [cite: 130-132].  

**​Step-by-Step Instructions**

1. ​Node Planning: You will need a total of 6 nodes:  
* ​Left Nodes: 2 client nodes (C1, C2).  
* ​Bridge Nodes: 2 central nodes (n1, n2).  
* ​Right Nodes: 2 server nodes (S1, S2).  

2. ​Link Configuration: * The links between clients and n1, and servers and n2, are "access links."  
* ​[cite_start]The link between n1 and n2 is the "bottleneck link" or "bridge".  
3. ​IP Addressing: Each point-to-point connection requires its own subnet (e.g., 10.1.1.0, 10.1.2.0, etc.).  
4. ​Implementation: Save the code below as dumbbell_topology.cc in your scratch folder and run it using ./waf --run scratch/dumbbell_topology.

**​C++ Code Implementation**

```c++```
```
#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"

using namespace ns3;

int main (int argc, char *argv[])
{
  // 1. Create Nodes
  NodeContainer leftClients, rightServers, bridgeNodes;
  leftClients.Create (2);   // Client 0, Client 1
  rightServers.Create (2);  // Server 0, Server 1
  bridgeNodes.Create (2);   // n1 (Node 4), n2 (Node 5)

  // 2. Configure Point-to-Point Links
  PointToPointHelper accessLink;
  accessLink.SetDeviceAttribute ("DataRate", StringValue ("10Mbps"));
  accessLink.SetChannelAttribute ("Delay", StringValue ("2ms"));

  PointToPointHelper bottleneckLink;
  bottleneckLink.SetDeviceAttribute ("DataRate", StringValue ("1Mbps")); // Slower for bottleneck
  bottleneckLink.SetChannelAttribute ("Delay", StringValue ("10ms"));

  // 3. Connect Nodes (Install NetDevices)
  NetDeviceContainer devicesC1n1 = accessLink.Install (leftClients.Get(0), bridgeNodes.Get(0));
  NetDeviceContainer devicesC2n1 = accessLink.Install (leftClients.Get(1), bridgeNodes.Get(0));
  NetDeviceContainer devicesS1n2 = accessLink.Install (rightServers.Get(0), bridgeNodes.Get(1));
  NetDeviceContainer devicesS2n2 = accessLink.Install (rightServers.Get(1), bridgeNodes.Get(1));
  NetDeviceContainer devicesn1n2 = bottleneckLink.Install (bridgeNodes.Get(0), bridgeNodes.Get(1));

  // 4. Install Internet Stack
  InternetStackHelper stack;
  stack.InstallAll ();

  // 5. Assign IP Addresses (Each P2P link needs a separate subnet)
  Ipv4AddressHelper address;
  Ipv4InterfaceContainer interfaces;

  address.SetBase ("10.1.1.0", "255.255.255.0");
  interfaces = address.Assign (devicesC1n1);

  address.SetBase ("10.1.2.0", "255.255.255.0");
  interfaces = address.Assign (devicesC2n1);

  address.SetBase ("10.1.3.0", "255.255.255.0");
  interfaces = address.Assign (devicesS1n2);

  address.SetBase ("10.1.4.0", "255.255.255.0");
  interfaces = address.Assign (devicesS2n2);

  address.SetBase ("10.1.5.0", "255.255.255.0");
  interfaces = address.Assign (devicesn1n2);

  // 6. Global Routing (Essential for multi-hop topology)
  Ipv4GlobalRoutingHelper::PopulateRoutingTables ();

  // 7. Verify with a simple Ping or Echo
  UdpEchoServerHelper echoServer (9);
  ApplicationContainer serverApp = echoServer.Install (rightServers.Get (0));
  serverApp.Start (Seconds (1.0));
  serverApp.Stop (Seconds (10.0));

  UdpEchoClientHelper echoClient (Ipv4Address ("10.1.3.1"), 9); // Server 1 IP
  echoClient.SetAttribute ("MaxPackets", UintegerValue (1));
  echoClient.SetAttribute ("Interval", TimeValue (Seconds (1.0)));
  echoClient.SetAttribute ("PacketSize", UintegerValue (1024));

  ApplicationContainer clientApp = echoClient.Install (leftClients.Get (0));
  clientApp.Start (Seconds (2.0));
  clientApp.Stop (Seconds (10.0));

  Simulator::Run ();
  Simulator::Destroy ();
  return 0;
}

```

**Analysis and Lab Record Tips**

* Routing Table: Since this is a multi-hop network (Client -> n1 -> n2 -> Server), you must call Ipv4GlobalRoutingHelper::PopulateRoutingTables() so the nodes know how to reach nodes that are not directly connected.
* Bottleneck: Notice the bottleneck link (n1 to n2) has a lower data rate (1Mbps) than the access links (10Mbps). This is the "dumbbell bridge capacity" mentioned in later sessions.  
* Output: Ensure you capture the terminal output showing the "Received 1024 bytes" message to prove connectivity between the two sides of the dumbbell.
