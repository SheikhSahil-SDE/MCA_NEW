# Session-02

# 1. Measure the throughput (end to end) while varying latency in the network created in Session-01.


We must modify the point-to-point network from Session-1 to measure performance metrics. The goal is to observe how increasing the network delay (latency) affects the overall throughput.
Step-by-Step Instructions
Modify the Channel Attribute: In your script, you will change the Delay value in the PointToPointHelper.  
Use FlowMonitor: This is a powerful NS-3 tool that automatically tracks every packet and calculates statistics like throughput, delay, and packet loss.  
Calculate Throughput: Throughput is calculated using the formula:

\text{Throughput (Kbps)} = \frac{\text{Total Received Bytes} \times 8}{\text{Simulation Time} \times 1024}
[cite_start]Vary Latency: You should run the simulation at least three times, changing the delay each time (e.g., 2ms, 20ms, 100ms), and record the results in your lab observation book [cite: 55-57].

**C++ Code Implementation**
Save this code as throughput_latency.cc in your scratch folder.

```c++```
```
#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"
#include "ns3/flow-monitor-helper.h"

using namespace ns3;

int main (int argc, char *argv[])
{
  // Allow user to vary latency from command line
  std::string latency = "2ms"; 
  CommandLine cmd;
  cmd.AddValue ("latency", "Latency for the link", latency);
  cmd.Parse (argc, argv);

  NodeContainer nodes;
  nodes.Create (2);

  PointToPointHelper p2p;
  p2p.SetDeviceAttribute ("DataRate", StringValue ("5Mbps"));
  p2p.SetChannelAttribute ("Delay", StringValue (latency)); // Varying this value

  NetDeviceContainer devices = p2p.Install (nodes);

  InternetStackHelper stack;
  stack.Install (nodes);

  Ipv4AddressHelper address;
  address.SetBase ("10.1.1.0", "255.255.255.0");
  Ipv4InterfaceContainer interfaces = address.Assign (devices);

  // Setup a BulkSend application to maximize throughput
  uint16_t port = 9;
  BulkSendHelper source ("ns3::TcpSocketFactory",
                         InetSocketAddress (interfaces.GetAddress (1), port));
  source.SetAttribute ("MaxBytes", UintegerValue (0)); // Unlimited data
  ApplicationContainer sourceApps = source.Install (nodes.Get (0));
  sourceApps.Start (Seconds (1.0));
  sourceApps.Stop (Seconds (10.0));

  PacketSinkHelper sink ("ns3::TcpSocketFactory",
                         InetSocketAddress (Ipv4Address::GetAny (), port));
  ApplicationContainer sinkApps = sink.Install (nodes.Get (1));
  sinkApps.Start (Seconds (0.0));
  sinkApps.Stop (Seconds (10.0));

  // Install FlowMonitor to measure throughput
  FlowMonitorHelper flowmon;
  Ptr<FlowMonitor> monitor = flowmon.InstallAll ();

  Simulator::Stop (Seconds (10.0));
  Simulator::Run ();

  // Extract and Print Throughput
  monitor->CheckForLostPackets ();
  Ptr<Ipv4FlowClassifier> classifier = DynamicCast<Ipv4FlowClassifier> (flowmon.GetClassifier ());
  std::map<FlowId, FlowMonitor::FlowStats> stats = monitor->GetFlowStats ();

  for (std::map<FlowId, FlowMonitor::FlowStats>::const_iterator i = stats.begin (); i != stats.end (); ++i)
    {
      Ipv4FlowClassifier::FiveTuple t = classifier->FindFlow (i->first);
      if (t.sourceAddress == "10.1.1.1") // Focus on the sender's flow
        {
          double throughput = i->second.rxBytes * 8.0 / (i->second.timeLastRxPacket.GetSeconds() - i->second.timeFirstTxPacket.GetSeconds()) / 1024;
          std::cout << "Latency: " << latency << " | Throughput: " << throughput << " Kbps" << std::endl;
        }
    }

  Simulator::Destroy ();
  return 0;
}

```
**How to Perform the Experiment**

Run the script multiple times with different latency arguments to observe the relationship:

1. Low Latency: ./waf --run "scratch/throughput_latency --latency=2ms"
2. Medium Latency: ./waf --run "scratch/throughput_latency --latency=50ms"
3. High Latency: ./waf --run "scratch/throughput_latency --latency=200ms"


We noticed that as the latency increases, the TCP throughput generally decreases because the "Acknowledgement" packets take longer to return, causing the sender to wait. [cite_start]This observation is a critical part of our lab report for Session 2 [cite: 58-60].
