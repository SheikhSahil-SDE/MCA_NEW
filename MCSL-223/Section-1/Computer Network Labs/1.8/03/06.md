# 6. Install a TCP socket instance connecting other remaining client node with the remaining server node in session 2’s network topology.

We will extend your current dumbbell topology script by adding a second parallel TCP flow between the remaining nodes.  
​Step-by-Step Instructions
​Identify Remaining Nodes: In Session-2, you had two clients and two servers. If Task 5 used Client 0 and Server 0, Task 6 requires connecting Client 1 (left side) with Server 1 (right side).  
​Add a Second Sink: Install another PacketSink on Server 1. You must use a different port number (e.g., 50001) to avoid a port conflict with the first socket.  
​Add a Second Source: Install a BulkSendApplication on Client 1. Configure its "Remote" attribute to point to the IP address of Server 1.  
​Set Start/Stop Times: To observe how the two flows compete for the bottleneck bandwidth, you can start the second flow slightly after the first one (e.g., at 3.0 seconds).
​C++ Code Implementation (Add to your existing script)
​You can add this block of code immediately after your Task 5 application setup [cite: 133-134].  

```c++```
```
// --- TASK 6: SECOND TCP SOCKET INSTANCE ---
uint16_t port2 = 50001; // Use a different port

// Receiver: PacketSink on Server 1 (Node index 1 in rightServers)
Address sinkLocalAddress2 (InetSocketAddress (Ipv4Address::GetAny (), port2));
PacketSinkHelper sinkHelper2 ("ns3::TcpSocketFactory", sinkLocalAddress2);
ApplicationContainer sinkApp2 = sinkHelper2.Install (rightServers.Get (1));
sinkApp2.Start (Seconds (1.0));
sinkApp2.Stop (Seconds (10.0));

// Sender: BulkSend on Client 1 (Node index 1 in leftClients)
// Points to Server 1's IP address (from your interface container)
AddressValue remoteAddress2 (InetSocketAddress (iS1n2.GetAddress (0), port2));
BulkSendHelper sourceHelper2 ("ns3::TcpSocketFactory", Address());
sourceHelper2.SetAttribute ("Remote", remoteAddress2);
sourceHelper2.SetAttribute ("MaxBytes", UintegerValue (0)); 

ApplicationContainer sourceApp2 = sourceHelper2.Install (leftClients.Get (1));
sourceApp2.Start (Seconds (3.0)); // Start 1 second after the first flow
sourceApp2.Stop (Seconds (10.0));

// Enable additional tracing for the new interface
p2p.EnablePcapAll ("tcp-dumbbell-task6");

```

**Observations for the Lab Record**
[cite_start]Bandwidth Sharing: Because the bottleneck link (n1 to n2) has a limited capacity (e.g., 1Mbps), the two TCP flows will now compete for it [cite: 147-148].  
[cite_start]Throughput Drop: You will notice in your traces or FlowMonitor data that the throughput of the first flow drops when the second flow starts at 3.0 seconds.  
Fairness: Observe if the two flows eventually share the 1Mbps capacity equally (roughly 500Kbps each). This demonstrates TCP Fairness.
