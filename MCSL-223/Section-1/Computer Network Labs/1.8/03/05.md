# 5. Install a TCP socket instance connecting either of the client node with either of the server node in session 2’s network topology.

We will extend the dumbbell topology created in Session-2 by installing a TCP socket instance between one client and one server [cite: 130-133].  

**Step-by-Step Instructions**
1. [cite_start]Select Nodes: Identify one client from the left side (e.g., Client 0) and one server from the right side (e.g., Server 0) to establish the connection.  

2. Install the Sink: On the destination node (Server 0), install a PacketSink. This acts as the receiving end of the TCP socket.  

3. Install the Source: On the source node (Client 0), install a BulkSendApplication. This application is designed to send data as fast as the TCP socket allows, which is ideal for measuring performance.  

4. Configure Routing: Ensure that Ipv4GlobalRoutingHelper::PopulateRoutingTables() is called, as the packets must travel through the bridge nodes (n1 and n2) to reach the destination.

5. Monitor Traffic: Add tracing to observe the TCP handshake and data transfer.

**C++ Code Implementation**
Save this script as tcp_socket_dumbbell.cc in your scratch folder.

```c++```
```
#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"

using namespace ns3;

int main (int argc, char *argv[])
{
  // 1. Re-create the Dumbbell Topology (from Session 2)
  NodeContainer leftClients, rightServers, bridgeNodes;
  leftClients.Create (2);
  rightServers.Create (2);
  bridgeNodes.Create (2);

  PointToPointHelper p2p;
  p2p.SetDeviceAttribute ("DataRate", StringValue ("10Mbps"));
  p2p.SetChannelAttribute ("Delay", StringValue ("2ms"));

  // Connections
  NetDeviceContainer dC0n1 = p2p.Install (leftClients.Get(0), bridgeNodes.Get(0));
  NetDeviceContainer dC1n1 = p2p.Install (leftClients.Get(1), bridgeNodes.Get(0));
  NetDeviceContainer dS0n2 = p2p.Install (rightServers.Get(0), bridgeNodes.Get(1));
  NetDeviceContainer dS1n2 = p2p.Install (rightServers.Get(1), bridgeNodes.Get(1));
  
  // Bottleneck link
  p2p.SetDeviceAttribute ("DataRate", StringValue ("1Mbps"));
  NetDeviceContainer dn1n2 = p2p.Install (bridgeNodes.Get(0), bridgeNodes.Get(1));

  // 2. Install Internet Stack and Routing
  InternetStackHelper stack;
  stack.InstallAll ();

  Ipv4AddressHelper address;
  address.SetBase ("10.1.1.0", "255.255.255.0");
  Ipv4InterfaceContainer iC0n1 = address.Assign (dC0n1);
  address.SetBase ("10.1.2.0", "255.255.255.0");
  address.Assign (dC1n1);
  address.SetBase ("10.1.3.0", "255.255.255.0");
  Ipv4InterfaceContainer iS0n2 = address.Assign (dS0n2);
  address.SetBase ("10.1.4.0", "255.255.255.0");
  address.Assign (dS1n2);
  address.SetBase ("10.1.5.0", "255.255.255.0");
  address.Assign (dn1n2);

  Ipv4GlobalRoutingHelper::PopulateRoutingTables ();

  // 3. INSTALL TCP SOCKET INSTANCE
  uint16_t port = 50000;

  // Receiver: PacketSink on Server 0 (Right Side)
  Address sinkLocalAddress (InetSocketAddress (Ipv4Address::GetAny (), port));
  PacketSinkHelper sinkHelper ("ns3::TcpSocketFactory", sinkLocalAddress);
  ApplicationContainer sinkApp = sinkHelper.Install (rightServers.Get (0));
  sinkApp.Start (Seconds (1.0));
  sinkApp.Stop (Seconds (10.0));

  // Sender: BulkSend on Client 0 (Left Side)
  // Connects to the IP of Server 0 (interface index 0 of the S0-n2 link)
  AddressValue remoteAddress (InetSocketAddress (iS0n2.GetAddress (0), port));
  BulkSendHelper sourceHelper ("ns3::TcpSocketFactory", Address());
  sourceHelper.SetAttribute ("Remote", remoteAddress);
  sourceHelper.SetAttribute ("MaxBytes", UintegerValue (0)); // Unlimited transfer

  ApplicationContainer sourceApp = sourceHelper.Install (leftClients.Get (0));
  sourceApp.Start (Seconds (2.0));
  sourceApp.Stop (Seconds (10.0));

  // 4. Enable Tracing for Lab Record
  p2p.EnablePcapAll ("tcp-dumbbell-task5");

  Simulator::Run ();
  Simulator::Destroy ();
  return 0;
}

```

**Observations for Lab Record**

* TCP Handshake: When you open the generated .pcap file in Wireshark, you will see the standard 3-way handshake (SYN, SYN-ACK, ACK) occurring between the Client and Server IP addresses.

* Multi-hop Path: Note that the packets are being routed from 10.1.1.1 (Client) to 10.1.3.1 (Server) through the bridge nodes, which is verified by the source and destination MAC addresses in the trace [cite: 123-125].  

* TCP Congestion Control: Since the bridge is a bottleneck (1Mbps), you may observe TCP slowing down its transmission rate to avoid dropping packets at node n1.
