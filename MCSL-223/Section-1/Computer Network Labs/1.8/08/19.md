# 19. Use the setup made in session 2 and monitor the traffic flow, plot the packets received.

We will return to the Dumbbell Topology created in Session-2 to perform an in-depth traffic analysis. This session focuses on observing how multiple flows interact over a shared bottleneck link and visualizing that data through plotting.

**​Step-by-Step Instructions**
* ​Reconstruct the Topology: Set up 6 nodes (2 Clients, 2 Routers/Bridge nodes, 2 Servers).
* ​Bottleneck Link: Ensure the link between the two bridge nodes (n1 and n2) has a lower data rate (e.g., 1Mbps) compared to the access links (e.g., 10Mbps) to create a congestion point.
* ​Install Applications: Set up a TCP flow (e.g., Client 0 to Server 0) and a UDP flow (e.g., Client 1 to Server 1).
​Monitor with FlowMonitor: Use the FlowMonitor module to capture real-time statistics for every individual flow passing through the bottleneck.
* ​Data Extraction: Program the simulation to write the timestamp and the number of packets received at the servers to a .dat file.

**​C++ Code Implementation**
​Save this code as dumbbell_monitor.cc in your scratch folder.

```c++```
```
#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"
#include "ns3/flow-monitor-helper.h"

using namespace ns3;

int main (int argc, char *argv[])
{
  NodeContainer leftClients, rightServers, routers;
  leftClients.Create (2);
  rightServers.Create (2);
  routers.Create (2);

  // Access links (Higher Bandwidth)
  PointToPointHelper accessLink;
  accessLink.SetDeviceAttribute ("DataRate", StringValue ("10Mbps"));
  accessLink.SetChannelAttribute ("Delay", StringValue ("2ms"));

  // Bottleneck link (Lower Bandwidth)
  PointToPointHelper bottleneckLink;
  bottleneckLink.SetDeviceAttribute ("DataRate", StringValue ("1Mbps"));
  bottleneckLink.SetChannelAttribute ("Delay", StringValue ("10ms"));

  // Connect Nodes
  NetDeviceContainer dC0R1 = accessLink.Install (leftClients.Get(0), routers.Get(0));
  NetDeviceContainer dC1R1 = accessLink.Install (leftClients.Get(1), routers.Get(0));
  NetDeviceContainer dS0R2 = accessLink.Install (rightServers.Get(0), routers.Get(1));
  NetDeviceContainer dS1R2 = accessLink.Install (rightServers.Get(1), routers.Get(1));
  NetDeviceContainer dR1R2 = bottleneckLink.Install (routers.Get(0), routers.Get(1));

  InternetStackHelper stack;
  stack.InstallAll ();

  Ipv4AddressHelper address;
  address.SetBase ("10.1.1.0", "255.255.255.0"); address.Assign (dC0R1);
  address.SetBase ("10.1.2.0", "255.255.255.0"); address.Assign (dC1R1);
  address.SetBase ("10.1.3.0", "255.255.255.0"); Ipv4InterfaceContainer iS0 = address.Assign (dS0R2);
  address.SetBase ("10.1.4.0", "255.255.255.0"); Ipv4InterfaceContainer iS1 = address.Assign (dS1R2);
  address.SetBase ("10.1.5.0", "255.255.255.0"); address.Assign (dR1R2);

  Ipv4GlobalRoutingHelper::PopulateRoutingTables ();

  // TCP Application
  uint16_t port1 = 8080;
  BulkSendHelper source1 ("ns3::TcpSocketFactory", InetSocketAddress (iS0.GetAddress (0), port1));
  source1.Install (leftClients.Get (0)).Start (Seconds (1.0));
  PacketSinkHelper sink1 ("ns3::TcpSocketFactory", InetSocketAddress (Ipv4Address::GetAny (), port1));
  sink1.Install (rightServers.Get (0)).Start (Seconds (0.5));

  // UDP Application (Starts later to show impact)
  uint16_t port2 = 9090;
  OnOffHelper source2 ("ns3::UdpSocketFactory", InetSocketAddress (iS1.GetAddress (0), port2));
  source2.SetAttribute ("DataRate", StringValue ("800kbps"));
  source2.Install (leftClients.Get (1)).Start (Seconds (5.0));
  PacketSinkHelper sink2 ("ns3::UdpSocketFactory", InetSocketAddress (Ipv4Address::GetAny (), port2));
  sink2.Install (rightServers.Get (1)).Start (Seconds (0.5));

  // MONITORING
  FlowMonitorHelper flowmon;
  Ptr<FlowMonitor> monitor = flowmon.InstallAll ();

  Simulator::Stop (Seconds (15.0));
  Simulator::Run ();

  monitor->SerializeToXmlFile("session8_results.xml", true, true);
  
  Simulator::Destroy ();
  return 0;
}

```
**Plotting the Packets Received**

To visualize the packets received over time, you can extract the data from the generated XML file or add a trace sink. To plot it effectively for your lab record:

1. Analyze the Data: Look at the "rxPackets" field in the session8_results.xml.
2. Gnuplot Script: Create a small file named plot_packets.plt:

```gnuplot```
```
set title "Packets Received over Time"
set xlabel "Time (s)"
set ylabel "Cumulative Packets"
plot "packets_data.dat" using 1:2 with lines title "TCP Flow", \
     "packets_data.dat" using 1:3 with lines title "UDP Flow"
```

3. Key Observation: You will notice that the rate of TCP packets received (the slope of the line) decreases significantly after t=5.0 seconds. This is because the UDP flow starts and "clogs" the bottleneck link, forcing TCP to reduce its congestion window as discussed in your MCS-218 textbook regarding congestion control.
