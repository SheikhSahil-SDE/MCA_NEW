# 17. Send packets to respective clients from both the servers

We must configure the nodes designated as "Servers" to initiate packet transmissions back to the "Client" nodes.

​This task demonstrates bidirectional traffic flow or the ability of any node in a peer-to-peer CSMA network to act as a sender [cite: 15, 212-213].
  
**​Step-by-Step Instructions**

1. ​Identify Senders: In this task, Node 1 and Node 3 (the servers from the previous setup) will act as the traffic sources.  
2. ​Identify Receivers: Node 0 and Node 2 (the original clients) will now act as the receivers (Sinks).  
3. ​[cite_start]Configure Applications: * Install a PacketSink on Node 0 and Node 2 to catch incoming data.  
     * ​Install a BulkSendApplication (for TCP) or OnOffApplication (for UDP) on Node 1 and Node 3 to send data.  
4. ​IP Addressing: Ensure the senders target the specific IP addresses assigned to the client nodes on the CSMA bus [cite: 224-225].  
5. ​Execution: Run the simulation and use the terminal output to confirm that packets sent by the "Servers" are successfully received by the "Clients." 
 
**​C++ Code Implementation**
​Save this script as server_to_client_flow.cc in your scratch folder.  

```c++```
```
#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/csma-module.h"
#include "ns3/internet-module.h"
#include "ns3/applications-module.h"

using namespace ns3;

int main (int argc, char *argv[])
{
  NodeContainer nodes;
  nodes.Create (4);

  CsmaHelper csma;
  csma.SetChannelAttribute ("DataRate", StringValue ("5Mbps"));
  csma.SetChannelAttribute ("Delay", StringValue ("2ms"));
  NetDeviceContainer devices = csma.Install (nodes);

  InternetStackHelper stack;
  stack.Install (nodes);

  Ipv4AddressHelper address;
  address.SetBase ("10.1.1.0", "255.255.255.0");
  Ipv4InterfaceContainer interfaces = address.Assign (devices);

  // Ports for the two pairs
  uint16_t port1 = 10001;
  uint16_t port2 = 10002;

  // --- TASK 17: SEND FROM SERVERS (N1, N3) TO CLIENTS (N0, N2) ---

  // 1. RECEIVERS (The original Clients: Node 0 and Node 2)
  PacketSinkHelper sink0 ("ns3::TcpSocketFactory", InetSocketAddress (Ipv4Address::GetAny (), port1));
  ApplicationContainer sinkApp0 = sink0.Install (nodes.Get (0));
  sinkApp0.Start (Seconds (0.5));

  PacketSinkHelper sink2 ("ns3::UdpSocketFactory", InetSocketAddress (Ipv4Address::GetAny (), port2));
  ApplicationContainer sinkApp2 = sink2.Install (nodes.Get (2));
  sinkApp2.Start (Seconds (0.5));

  // 2. SENDERS (The original Servers: Node 1 and Node 3)
  // TCP Flow: Node 1 -> Node 0
  BulkSendHelper source1 ("ns3::TcpSocketFactory", InetSocketAddress (interfaces.GetAddress (0), port1));
  source1.SetAttribute ("MaxBytes", UintegerValue (512000)); // Send 512KB
  ApplicationContainer sourceApp1 = source1.Install (nodes.Get (1));
  sourceApp1.Start (Seconds (1.0));

  // UDP Flow: Node 3 -> Node 2
  OnOffHelper source3 ("ns3::UdpSocketFactory", InetSocketAddress (interfaces.GetAddress (2), port2));
  source3.SetAttribute ("DataRate", StringValue ("1Mbps"));
  source3.SetAttribute ("PacketSize", UintegerValue (1024));
  ApplicationContainer sourceApp3 = source3.Install (nodes.Get (3));
  sourceApp3.Start (Seconds (1.5));

  // Enable Tracing
  csma.EnablePcapAll ("task17-server-to-client");

  Simulator::Stop (Seconds (10.0));
  Simulator::Run ();
  Simulator::Destroy ();
  return 0;
}

```
**Analysis for the Lab Record**


* Role Reversal: In this simulation, the "Server" hardware (Node 1 and Node 3) is initiating the communication. [cite_start]This reflects how real-world servers push updates or data streams to clients after a connection is established.  
* Packet Capture: In your Wireshark traces, look for the source IP 10.1.1.2 (Node 1) sending to destination 10.1.1.1 (Node 0). This confirms the server-to-client direction.  
* Protocol Differences: Observe that the TCP flow (Node 1 to Node 0) will show a steady stream of segments and acknowledgments, while the UDP flow (Node 3 to Node 2) will show a burst of packets at 1Mbps without a back-and-forth handshake.
